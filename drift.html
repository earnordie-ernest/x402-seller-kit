Measured live 2026-11-19T21:05:00Z · 79 stale rows across 18 hosts. Every row re-probed 3×: index payTo (from the CDP Bazaar catalogue) vs the payTo the endpoint's actual 402 challenge asks for.

Why this matters. When a seller migrates wallets but their catalogue rows are not re-indexed, buyers who decide from the index send USDC to the old address. The payment is real, the seller never sees it. The defect is invisible from the seller's own dashboard because their endpoint answers correctly — only the listing is wrong.

Method: crawl the CDP Bazaar index per host, group Base payTo, then probe each listed resource's live 402 (JSON body and the base64 payment-required header) and compare the exact URL's live payTo against the one the index lists for that URL. A row is stale only when it returns a stable 402 whose Base payTo differs from the indexed one. A 404/405/empty body is never counted as stale.
